# Data card

## Provenance

All plans and transcript cases are fictional, authored for this repository with AI
assistance. They do not come from Penn Medicine, an EHR, a research participant,
or public patient records. Medication instructions are fictional scenario contents,
not recommended regimens. Two plans cover wound care and home exercise follow-up.

`data/cases.json` has 16 examples and per-target labels plus barrier categories.
The same project authoring process designed the rules and the examples. There is
no independent annotation, patient sampling, held-out test split, or external validation.
Challenge cases intentionally retain paraphrase, correction, and negated-barrier errors.

## Label policy

- `covered`: all specified details are explicitly and unambiguously restated.
- `missing`: the target is absent from the explanation.
- `needs_review`: incomplete, uncertain, negated, or self-corrected statement.
- `possible_conflict`: an explicit incompatible instruction is stated.

Conflicting options in an unresolved “once or twice” statement receive possible
conflict. A speaker who explicitly self-corrects receives needs_review. These are
project annotation conventions, not clinical standards. A missing mention is not
evidence that the person does not understand the instruction.

Barrier labels identify expressed logistical concerns, not diagnoses or social-risk
scores. The baseline does not reliably resolve barrier negation; one case measures
that error explicitly.

## Audio

`teachback.wav` is generated by Windows `System.Speech` from the sample transcript.
`provenance.json` records the installed voice. It is a single artificial voice reading
a single script. Noise is seeded Gaussian noise at nominal 10 dB SNR relative to
whole-file RMS, added before clipping. This is not a recording of a noisy hospital.
The noisy copy is reproducible and excluded from Git by `outputs/`.

No claims about accents, disability, age, language groups, microphones, overlap,
or noisy real-world clinical settings can be drawn from this fixture.

## Stewardship

No application database is used. Uploaded audio is written to a temporary file for
inference and deleted in a `finally` block; abrupt process termination can leave
temporary files. Transcripts and reports live in Streamlit session memory until
the session is cleared. Downloaded JSON is retained wherever the user saves it.
Ignoring files in Git is not de-identification or access control. The synthetic flag
and consent gate are self-attestations, not PHI detection. Use synthetic data only.
